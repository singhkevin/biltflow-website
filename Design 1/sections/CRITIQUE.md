# Section redesigns — cross-section critique

Five sections were redesigned in parallel, then reviewed **as a set** by a sixth agent whose
brief was to be blunt about collective load, consistency and honesty. Its verdict is below,
unedited. Read it before integrating any of these into the page.

---

**1. CONSISTENCY.** Palette, radius and easing hold: only `cubic-bezier(.4,0,.2,1)` and `linear` across all five, `border-radius:0` universal, zero gradients, zero shadows. Everything above that drifts. Five different eyebrows: orange rule *after* (integrations), orange bar *before* (compounding), orange number + bottom border (roles), full-width 3px orange rule + FIG. line (repurpose), nothing at all (eve). Figure numbering contradicts itself on one page — eve is "Fig. 02", roles "Fig. 09", repurpose "FIG. 10", compounding has none, integrations has "Fig. — connection schedule" with no number; section numbers appear on three of five. `integrations.html` is the type outlier: h2 48px/600 against 44px/500 everywhere else. Gutters are 100/100/96/80/80px, so four different left edges. `compounding.html` invents six greys outside the system (#E7ECEF #D5DEE4 #BFCBD4 #A9B8C3 #BCC5CC #E4E8EB) and is the only section with fills; repurpose uses #000000 on hover, a colour nowhere else. Practical blocker: `.page .sec .head .col .slot .key .legend .ref .count .foot .mono` are defined differently in all five files. Combining these is a rebuild against one stylesheet, not a paste.

**2. COLLECTIVE LOAD.** Keep two. **repurpose** — the accordion is a reading control, not an effect; it is the only interaction that reveals text the buyer actually wants. **integrations** — the hover trace answers the literal objection ("do you work with my stack") and the record panel has no static equivalent. Make the other three fully static, entrance animations included. Five one-shot reveals means the page assembles itself as he scrolls, which *is* complaint (1). Specifically: kill eve's waveform outright; kill roles' 13-column fill and the ruler resolve (the per-card strips already say it); kill compounding's deposit wipe — the orange staircase is the argument and should be visible in the first glance, not built over 1.2s.

**3. HONESTY.** Worst: repurpose RFI-01 quotes "we already run **eleven** systems" while integrations headlines "**Twelve** systems. One record." on the same page. "180-apartment build · Sydney" is the only hard figure anywhere and it is attached to a deliberately unattributable quote — unverifiable by construction; cut the number. Roughly 150 unverified domain assertions ship here: 48 record-type lines, 27 relationship labels, 78 stage assignments — and roles prints "stage assignment drafted from construction practice — to be confirmed" on the page, inviting doubt about everything else. Twelve third-party marks used nominatively, three showing the wrong mark (Oracle for Aconex, Viewpoint for Jobpac, RIB for CostX) and two cropped to strip parent-company straplines — the crop is the legal exposure, the mislabelling is the credibility one; this buyer knows those logos. Cut Excel's "The one file nobody replaces" and Outlook's "Approvals buried in threads" — mocking his tools inside the section promising to keep them. RFI-03's "not pooled into something that prices a competitor's job" is an enforceable promise, and its "[ Data & IP schedule — with counsel, not yet issued ]" stamp is itself a fabrication if no lawyer is engaged. Also invented: "two years", "SUPERVISED" and all three mode lines, compounding's L1→L4 unlock. Four visible bracketed placeholders across four sections: one reads as honest, four read as unfinished.

**4. WEAKEST: `/Users/kevinsingh/Desktop/Builtflow Website/Design 1/sections/eve-provenance.html`.** Highest invented-to-verifiable ratio, largest footprint, three bullets returned per interaction. Fix: drop the radial and the waveform; redraw as a static left-to-right chain in build order with EVE as one labelled band running under every link, so "through EVE" is drawn once instead of nine times on hover; cut 27 labels to the 8 sequential ones a QS can sign in a single pass; pull the COPILOT/SUPERVISED/AUTOPILOT slider until the middle detent and autopilot wording are confirmed.

**5. RULE BREAKS.** No literal breaks — nothing bounces, corners are sharp, no gradients or shadows. Two flags: eve's waveform is a continuous rAF loop, the page's only perpetual motion, and violates the spirit; and `integrations.html` line 5 sets `<meta name="viewport" content="width=1440">` with zero breakpoints — merged into one page that kills mobile for all five sections. `eve-provenance.html` also has no breakpoints.

## What each agent built, and what it invented

### `integrations`

**Idea.** The static 6x2 logo grid becomes a riser diagram: twelve vendor systems wired down two vertical buses into a single central ONE RECORD card, so the connection is drawn as construction wiring rather than asserted by a caption. Framing each vendor's contents as "what lives in Aconex today" carries the argument "you keep these, we unify them" without claiming a connector that does not yet exist.

**What moves.** Two things, never simultaneously. (1) On first intersection the twelve hairline routes draw themselves once in a 55ms stagger via stroke-dashoffset, then rest permanently — establishing the lines as wiring, not decoration. (2) On hover or keyboard focus, exactly one route redraws in Safety Orange from that card to the record (500ms, linear), the card's port mark fills orange, an arrival square lands on the record edge, and the record panel swaps to that system's four record types. Everything else holds still. Gated on IntersectionObserver so the section is inert off-screen; under prefers-reduced-motion the draw is dropped and only the state swap remains. Vanilla JS ~2.4KB, no library, cards are buttons so tabbing drives it.

**Invented — needs human verification.**

1) RECORD-TYPE LISTS — all 48 items ("RFIs and responses", "Transmittals", "Cost codes", "Retention balances", etc.) are my description of what each vendor tool typically holds on a project. Plausible domain knowledge, not sourced from the vendors or from Biltflow. Two are deliberate jokes at the reader's expense and may land badly with a sceptical 55-year-old: Excel = "The one file nobody replaces", Outlook = "Approvals buried in threads". Biltflow must sign off on all wording.

2) LOGO FILE MISMATCHES (found during build, corrected but needs confirmation) — three supplied files are parent-brand marks, not product wordmarks: logos/aconex.svg is the ORACLE wordmark, logos/jobpac.png is the VIEWPOINT wordmark, logos/costx.svg is the RIB wordmark. Those three cards now render mark + product name in Archivo ("ORACLE Aconex", "Viewpoint Jobpac", "RIB CostX"), which is the real product lockup — but a human should confirm these lockups are current and correctly formed.

3) LOGO CROPS — bluebeam.svg viewBox tightened from 0 0 210 47 to 0 0 210 24, and payapps.png cropped 1036x212 to 1036x122, to remove the "A NEMETSCHEK COMPANY" and "An AUTODESK Company" straplines, which were illegible smudges at 15px and imply irrelevant corporate parentage. Source files in ../logos/ are untouched; only the inlined copies are cropped. Legal may have a view on cropping a registered lockup.

4) LOGOS INLINED AS BASE64 — the brief required a standalone page, and relative ../logos/ paths break the moment the file is moved or previewed in a sandbox. A one-line swap back to filesystem paths is documented in a code comment above the loader.

5) COPY I WROTE — column headings "Project & commercial systems" / "Finance, measure & messaging"; the "How to read this" legend; the rest-state line "Twelve systems. One record."; and the full nominative-use footnote ("Product names and logos are the property of their respective owners... No partnership, affiliation or endorsement is implied"). 6) HONESTY PLACEHOLDER — "[ Connector scope to confirm ]" sits in a dashed box inside the record panel and must stay until real per-system connector scope exists. No metrics, no customer names, no product screenshots anywhere in the section; verified by grep (0 percentages in copy, 0 gradients, 0 shadows, border-radius:0 only, no emoji).

### `eve-provenance`

**Idea.** Merges the nine static provenance cards and the flat orchestration SVG into one radial diagram: the nine document types ring EVE in the order a building produces them, and selecting any document routes its real relationships THROUGH the EVE hub — never document-to-document — so the section argues the product's actual claim (it knows how these refer to each other) instead of just listing inputs. Source spoke turns Safety Orange with an arrow pointing into EVE; the three related spokes turn data blue with arrows pointing out, each annotated with the relationship ("PRICED FROM", "SPLIT INTO", "AWARDED ON"). A side readout panel repeats every relation in words for a reader who won't squint at a diagram. Below sits the script's real control, COPILOT — SUPERVISED — AUTOPILOT.

**What moves.** One sustained motion only: the waveform inside the EVE plate. It is a dead-flat hairline at rest, resolves into signal while a document is selected, and eases back to flat when you let go — EVE thinking, not EVE idling, and no idle loop. Everything else is instant state, not animation: spokes recolour and label (160ms linear), cards take a dark/blue border or drop to 45% (180ms linear), the slider knob translates on click (220ms cubic-bezier(.4,0,.2,1)). Verified in-browser: waveform animates while visible and active; IntersectionObserver cancels the rAF and flattens the line off-screen, then resumes on return; pulse() bails entirely under prefers-reduced-motion so the rAF never starts and the line stays flat while every state change still works. Hover previews, click pins, Enter/Space and tab-focus work on all nine nodes. Behaviour code is 3,700 bytes of vanilla JS (2.6 KB gzipped whole script), no library, no WebGL.

**Invented — needs human verification.**

1) ALL 27 RELATIONSHIP LABELS plus the one-line description of each of the nine documents — "TAKEN OFF", "PRICED FROM", "SCHEDULED", "SPLIT INTO", "AWARDED ON", "CLAIMED VS", "CONDITION OF", "EVIDENCED BY" etc. These are written to sound like a QS or contracts manager and are domain-plausible, but they are NOT confirmed against Biltflow's actual data model. They are the whole credibility of the section — a quantity surveyor must read and correct them before this ships. 2) "SUPERVISED" as the middle detent of the control, and all three mode descriptions ("EVE drafts. A person approves every one..." / "acts inside limits you set" / "closes the routine loop on its own"). The locked script specifies only the two ends, COPILOT and AUTOPILOT; confirm a middle state exists and that the autopilot wording does not overstate what is built. 3) The headline "Built on real construction. EVE holds it together." and the deck are new copy merging the two old section heads. 4) DELIBERATE REMOVAL, needs a decision: the previous section's "$5B+ REAL HIGH-DENSITY RESIDENTIAL CONSTRUCTION PROJECT DATA" was an unverified metric and is gone. It is replaced by a visibly bracketed placeholder — "[ Training corpus — scale and source pending verification. No figure to be published until confirmed. ]". Someone must either substantiate a corpus figure or approve shipping without one. 5) Verified clean by grep: only border-radius:0, zero gradients, zero shadows, zero emoji, only cubic-bezier(.4,0,.2,1) easing, exact palette only, no external JS, and the only numbers rendered on screen are the 01–09 indices of the nine documents actually drawn.

### `compounding`

**Idea.** Redrawn as a section through the ground: each project is a fixed-depth excavation in which real knowledge from completed buildings displaces the generic industry baseline hatch. The four PROJECT 01-04 columns and the four named layers (RATES L1, DURATIONS L2, SUBCONTRACTOR PERFORMANCE L3, DEFECT PATTERNS L4) are kept exactly, but the emphasis is inverted — the big empty white boxes are gone, the header shrinks to a grid ref, the approved caption and a PRIOR BUILDINGS list, and the strata now own the frame. Layer names moved to a left legend gutter so the four channels align as readable rows across all columns. A 3px Safety Orange rule marks the base of real knowledge and steps down like a staircase from 01 to 04 — that stepped line is the whole argument in one glance. Equal depth is drawn in every column; only the composition changes, so 01 is almost all hatch and 04 is almost all solid named layers.

**What moves.** One coordinated deposit sequence, once. On IntersectionObserver entry (threshold 0.25) the strata are revealed downward column by column via clip-path inset wipes — 340ms each, cubic-bezier(.4,0,.2,1), 90ms stagger, ~1.2s total — with each column's orange knowledge-depth rule fading in last (200ms linear). Then the observer disconnects and the drawing rests. A 2.2s failsafe guarantees it is never left half-built. prefers-reduced-motion and no-JS both render the composed drawing with zero transitions. The only other state is hover: hovering a column drops the other columns' bands to opacity .42 and their captions to #9AA4AD, 120ms linear, colour/opacity only, no transform. ~1 KB of vanilla JS, no library, no loop, no parallax, no fade-up.

### `roles`

**Idea.** The client is right that the corner ring was decorative, so it is gone. Each role card now carries a 13-stage linear strip — owned stages solid Safety Orange, upstream dependencies hollow in data blue, everything else a faint 4px baseline mark — which is legible at card size in a way a 40px ring never was. Above the six cards sits one shared 13-column ruler with grid refs 01–13 and vertical mono stage names, and that ruler is the section's single interactive element: it is the same 13 stages at full size, so the small strips and the big ruler teach each other.

**What moves.** Exactly one element moves: the shared ruler. At rest it is a tally — each column's height is how many of the six roles sign for that stage — so CONSTRUCTION (3 roles) and COMPLIANCE/HANDOVER (2 each) stand up as the crowded seams where handovers actually fail. Hover or keyboard-focus any card and the ruler resolves to that one role: owned columns go solid, upstream columns go hollow blue, the rest drop to a single faint tick, stage names brighten or dim, and the mono readout renames itself ("CONSTRUCTION DIRECTOR — OWNS 3 · READS 5 UPSTREAM"). Then it rests. Colour and opacity only, 160ms linear, no loop, no parallax, no fade-up. The card itself gets a 3px orange left rule at 120ms and nothing else. On first scroll into view the thirteen columns fill left to right once (26ms stagger) and stop. IntersectionObserver unbinds the interaction entirely off-screen; prefers-reduced-motion kills every transition and the entrance. 2,553 bytes of vanilla JS, zero external scripts, zero libraries. Verified: computed border-radius is 0px on every element in the DOM, no box-shadow, no background-image (so no gradients), only the ten system colours, no horizontal overflow at 1440px or 390px, and cards are tab-focusable with the same resolve on focus.

### `repurpose`

**Idea.** The proof slot is repurposed into an RFI REGISTER — the construction document type this reader signs every week. The five real objections become numbered rows (RFI-01…05) in the buyer's own words, each carrying a status stamp: ANSWERED, ANSWERED · WITH A CONDITION, ANSWERED · CONTRACT PENDING, or OPEN. Two rows are deliberately stamped OPEN and left unanswered — implementation timeline ("Biltflow has not yet run a full lifecycle on a live high-density job, so we have no timeline we'd put in a contract") and price ("there is no price on this website because there isn't yet one worth publishing"). The strategic move: in an RFI register, open items are normal and a register with everything closed is the suspicious one. So "we can't answer that yet" stops reading as a weakness and starts reading as a document convention — which is the only honest way to run an objection section with zero customers. The two practitioner quotes are kept, relocated into a bordered SOURCE card in the header ("Source — practitioner interviews · unattributed at request") where they now explain the provenance of the register rather than standing in for testimonials. The empty dashed placeholders are dropped, and the bracketed-placeholder device is moved somewhere it does real work: a [ DATA & IP SCHEDULE — WITH COUNSEL, NOT YET ISSUED ] stamp inside the data-ownership answer, and a closing RFI-06 row reading [ YOUR QUESTION — NOT YET RAISED ] that carries the single CTA. Footnote: "No customer references appear on this page. Biltflow has none yet."

**What moves.** One accordion, exactly one row open at a time (row 01 open on load so it reads without interaction). Clicking a row closes the current one and opens the new one — a single coordinated 260ms cubic-bezier(.4,0,.2,1) gesture combining three CSS properties: the answer panel's height via grid-template-rows 0fr→1fr (no JS measurement, so it survives resize and font-load), an orange revision bar wiping down the left margin via transform: scaleY(0→1) with transform-origin top, and the +/− sign's vertical stroke collapsing via scaleY. No parallax, no fade-up, no loop, nothing to pause. Transitions are opt-in rather than opt-out: the CSS attaches them only under `.reg.is-live`, and an IntersectionObserver adds that class solely while the register is on screen — so off-screen state changes apply instantly, and prefers-reduced-motion bails from the observer entirely (plus a global 0.01ms transition override). 1,202 bytes of inline vanilla JS, no library. Verified in-browser: is-live true and transition-duration 0.26s while in view; toggle confirmed in both directions with aria-expanded tracking; keyboard-operable since each row header is a real <button> with aria-controls and a focus-visible ring.
